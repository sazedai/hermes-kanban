1. What Are Sub-Agents?

In Hermes Agent, a sub-agent is a child AI agent instance spawned by a parent agent to work on a specific task independently. Think of it as the parent agent hiring a specialized contractor: the contractor gets a clear brief, does the work in their own space, and returns only the final result.

Sub-agents are created using the delegate_task tool. Each sub-agent receives:

  • A fresh conversation — zero knowledge of the parent's history
  • Its own terminal session for running commands
  • A restricted toolset chosen by the parent (e.g., only ["web"] or ["terminal", "file"])
  • Only the goal and context explicitly passed by the parent
Key Insight

Only the sub-agent's final summary enters the parent's context window. All intermediate tool calls, searches, and reasoning steps stay isolated. This is the single most important architectural benefit of sub-agent delegation.

This design solves a fundamental problem in AI agent systems: context window pollution. When a single agent performs a complex multi-step task, every intermediate tool call, search result, and reasoning step accumulates in the context window. This degrades performance, increases costs, and can cause the agent to lose track of its original objective. Sub-agents keep the parent's context clean by absorbing all that intermediate work.

2. How delegate_task Works

The delegate_task tool is the primary mechanism for spawning sub-agents. It supports two modes: single task and parallel batch.

Single Task Mode

For straightforward delegation, you pass a single goal, optional context, and a toolset: 

delegate_task(
    goal="Debug why the test suite fails on line 42 of test_foo.py",
    context="Error: AssertionError in test_foo.py line 42. The project is at /home/user/myproject and uses Python 3.11 with pytest.",
    toolsets=["terminal", "file"]
)

The parent agent calls delegate_task, and the sub-agent begins working immediately. The parent's turn blocks until the sub-agent completes and returns its summary.

Parallel Batch Mode

For multiple independent tasks, pass an array of task objects. They run concurrently: 

delegate_task(tasks=[
    {
        "goal": "Research the current state of WebAssembly in 2025",
        "context": "Focus on: browser support, non-browser runtimes, language support",
        "toolsets": ["web"]
    },
    {
        "goal": "Research RISC-V server chip adoption in 2025",
        "context": "Focus on: server chips shipping, cloud providers, software ecosystem",
        "toolsets": ["web"]
    },
    {
        "goal": "Research quantum computing progress in 2025",
        "context": "Focus on: error correction, practical applications, key players",
        "toolsets": ["web"]
    }
])

By default, up to 3 sub-agents run concurrently. This limit is configurable via delegation.max_concurrent_children in config.yaml or the DELEGATION_MAX_CONCURRENT_CHILDREN environment variable. There is no hard ceiling — you can increase it as needed.

Model Override

You can route sub-agents to a different (often cheaper or faster) model: 

# In ~/.hermes/config.yaml
delegation:
  model: "google/gemini-flash-2.0"
  provider: "openrouter"

This is particularly useful for delegating simple research or formatting tasks to fast models while reserving the parent's powerful model for synthesis and decision-making.

3. The Isolated Context Model

The most critical concept in sub-agent delegation is context isolation. When a sub-agent is spawned, it starts with a completely fresh conversation. It has:

  • Zero knowledge of the parent's conversation history
  • No access to prior tool calls or their results
  • No awareness of what the parent was discussing before delegation
  • Only the goal and context fields passed by the parent
The Context Problem

If you delegate "fix the bug we were discussing," the subagent has no idea what bug you mean. You must pass file paths, error messages, project structure, and constraints explicitly. The sub-agent cannot see your screen, your prior messages, or your intentions — only what you write in the goal and context fields.

This isolation is a feature, not a limitation. It means:

  • No bias carryover — the sub-agent approaches the task fresh, without being influenced by the parent's earlier reasoning
  • Clean context windows — the parent's context stays focused on high-level orchestration
  • Parallel safety — multiple sub-agents can't accidentally share state or interfere with each other
  • Deterministic inputs — the sub-agent's behavior is fully determined by what the parent passes, making delegation reproducible

4. Parallel Execution & Concurrency

When running multiple sub-agents in batch mode, Hermes uses a ThreadPoolExecutor with the configured concurrency limit as max workers. Here's what happens under the hood:

[Parent Agent] │ ├─ delegate_task(tasks=[T1, T2, T3]) │ ▼ [ThreadPoolExecutor] (max_workers=3) ├──────────────────┬──────────────────┐ ▼ ▼ ▼ [Sub-Agent 1] [Sub-Agent 2] [Sub-Agent 3] toolsets: [web] toolsets: [web] toolsets: [web] │ │ │ ▼ ▼ ▼ [Results sorted by task index] │ ▼ [Parent synthesizes summaries]

Key behaviors:

  • Results are sorted by task index — regardless of which sub-agent finishes first, results are returned in the same order as the input array
  • Interrupt propagation — if the parent is interrupted (e.g., Ctrl+C), all active children are cancelled and their work is discarded
  • CLI progress display — in terminal mode, a tree-view shows tool calls from each sub-agent in real-time
  • Synchronous by default — delegate_task blocks the parent turn until all children complete
Synchronous = Interruptible

Because delegate_task is synchronous, if the parent turn is interrupted, all active children are cancelled and their work is lost. For durable long-running work, consider using terminal(background=True, notify_on_complete=True) or cron jobs instead.

5. Handoff Patterns & Shared Workspaces

For complex multi-step workflows, sub-agents need to pass work products to each other. Hermes supports this through the shared workspace pattern, where sub-agents read predecessor outputs from and write their own outputs to a shared directory.

The Pipeline-as-Code Pattern

The multi-agent-pipeline skill demonstrates a full pipeline-as-code approach. Workflows are defined as markdown files with dependency graphs: 

# Task Graph
T1 (researcher) → T2 (analyst) → T3,T4,T5,T6,T7 (writer, parallel) → T8 (reviewer) → T9 (writer)

# Dependency Levels
Level 0: T1          (no deps, starts immediately)
Level 1: T2          (needs T1)
Level 2: T3-T7       (needs T2, all run in parallel)
Level 3: T8          (needs all of T3-T7)
Level 4: T9          (needs T8)

Shared Workspace Structure

Each sub-agent reads from and writes to a shared workspace directory: 

workspaces/my-pipeline/
├── T1_output.md          # Research brief
├── T1_handoff.json       # Structured metadata
├── T2_output.md          # Messaging framework
├── T2_handoff.json
├── T3_output.md          # Landing page copy
├── ...
├── T8_output.md          # Review report
├── T8_handoff.json       # Issues list
├── T4_final.md           # Fixed email sequence
└── T9_changelog.md       # What changed and why

Handoff JSON Format

Each sub-agent writes a structured handoff file that downstream agents can consume: 

{
    "task_id": "T3",
    "status": "complete",
    "summary": "Landing page copy written, 487 words, focuses on pain points from T1 research",
    "output_file": "T3_output.md",
    "metadata": {
        "word_count": 487,
        "key_messages": ["speed", "reliability", "developer experience"],
        "sources_cited": 3
    }
}

Review-Revise Loop

A common pattern includes a reviewer task that reads all content outputs, compares them against the source of truth (e.g., a messaging framework), and either passes or requests revisions. If revisions are requested, a finalizer task patches the flagged files and produces a changelog.

6. Profiles vs. Sub-Agents: When to Use Which

Hermes Agent offers two forms of agent isolation: profiles and sub-agents. They serve different purposes and are not interchangeable.

Sub-Agents

  • Ephemeral — exist for one task, then disappear
  • Spawned dynamically by delegate_task
  • Fresh context every time
  • Restricted toolset chosen by parent
  • Return only a final summary
  • Share the parent's filesystem and state directory
  • Ideal for: parallel work, context isolation, one-off tasks

Profiles

  • Persistent — long-lived agent environments
  • Created with hermes profile create
  • Own memory, sessions, and conversation history
  • Full toolset (configured per-profile)
  • Own gateway, cron jobs, and skills
  • Separate state directory (~/.hermes/profiles/<name>/)
  • Ideal for: specialized agents, team bots, persistent services

The key distinction: sub-agents are task-level isolation; profiles are identity-level isolation. Use sub-agents when you want to parallelize work or keep context clean within a single session. Use profiles when you need a completely separate agent with its own personality, memory, and persistent state.

You can even combine the two: a profile-based agent can spawn its own sub-agents, creating a hierarchy of specialized workers.

7. Real-World Use Cases

Parallel Research & Synthesis

One of the most powerful applications is running multiple research tasks simultaneously. For example, evaluating three different technical approaches to a problem: 

delegate_task(tasks=[
    {
        "goal": "Evaluate PostgreSQL tsvector for full-text search in our Django app",
        "context": "Project uses Django 5.0, PostgreSQL 16. Assess: setup complexity, query capabilities, resource needs, maintenance.",
        "toolsets": ["web"]
    },
    {
        "goal": "Evaluate Elasticsearch via django-elasticsearch-dsl for our Django app",
        "context": "Same project. Assess: setup complexity, query capabilities, resource needs, maintenance.",
        "toolsets": ["web"]
    },
    {
        "goal": "Evaluate Meilisearch via meilisearch-python for our Django app",
        "context": "Same project. Assess: setup complexity, query capabilities, resource needs, maintenance.",
        "toolsets": ["web"]
    }
])
# Parent receives 3 independent evaluations and picks the best

Multi-Agent Stock Analysis

The advanced-stock-analysis skill demonstrates a sophisticated multi-agent debate pattern. Four analyst agents (Fundamental, Technical, Sentiment, Risk) analyze a stock independently, then engage in cross-examination and debate before reaching a consensus: 

# Round 1: All 4 analysts work in parallel
delegate_task(tasks=[
    {"goal": "Analyze AAPL fundamentals...", "context": "...", "toolsets": ["terminal", "web"]},
    {"goal": "Analyze AAPL technicals...", "context": "...", "toolsets": ["terminal", "web"]},
    {"goal": "Analyze AAPL sentiment...", "context": "...", "toolsets": ["terminal", "web"]},
    {"goal": "Assess AAPL risk...", "context": "...", "toolsets": ["terminal", "web"]}
])
# Parent collects results, runs bull vs bear debate, produces consensus

Marketing Content Pipeline

A 9-task pipeline that goes from audience research through messaging, parallel content creation (landing page, emails, social posts, blog, video script), review, and finalization. The writer tasks (T3-T7) all run in parallel after the messaging framework is established: 

# Level 2: Five content pieces written simultaneously
delegate_task(tasks=[
    {"goal": "Write landing page copy (≤500 words)", "context": "READ T2_output.md first. Use messaging framework.", "toolsets": ["file"]},
    {"goal": "Write 3-email launch sequence", "context": "READ T2_output.md first.", "toolsets": ["file"]},
    {"goal": "Write 6 social posts (LinkedIn, X, Instagram)", "context": "READ T2_output.md first.", "toolsets": ["file"]},
    {"goal": "Write SEO blog post (1500 words)", "context": "READ T2_output.md first.", "toolsets": ["file"]},
    {"goal": "Write YouTube Shorts script (60 sec)", "context": "READ T2_output.md first.", "toolsets": ["file"]}
])

Code Review & Security Audit

Delegating a security review to a fresh-context sub-agent ensures the reviewer approaches the code without any preconceptions from the parent's earlier analysis: 

delegate_task(
    goal="Review src/auth/ for security issues and fix any found",
    context="""Project at /home/user/webapp. Python 3.11, Flask, PyJWT, bcrypt.
    Auth files: src/auth/login.py, src/auth/jwt.py, src/auth/middleware.py
    Test command: pytest tests/auth/ -v
    Focus on: SQL injection, JWT validation, password hashing, session management.
    Fix issues found and verify tests pass.""",
    toolsets=["terminal", "file"]
)

8. Pitfalls & Best Practices

Pass Explicit Context

The number one mistake in sub-agent delegation is under-specifying context. Remember: the sub-agent knows nothing about your conversation. Always include:

  • File paths and project locations
  • Error messages and stack traces (verbatim)
  • Technology stack and versions
  • Constraints and requirements
  • Expected output format and location

Choose the Right Toolset

Restrict the sub-agent's toolset to only what it needs. This reduces the attack surface and keeps the sub-agent focused:

Toolset Pattern Use Case
["terminal", "file"] Code work, debugging, file editing
["web"] Research, fact-finding, documentation lookup
["terminal"] Running tests, builds, deployments
["file"] Reading/writing files without terminal access

Don't Delegate What You Can Do Directly

Sub-agent delegation has overhead. Don't delegate tasks that are better handled directly:

  • Single tool call — use the tool directly
  • Mechanical multi-step work — use execute_code
  • Tasks needing user interaction — sub-agents can't use clarify
  • Quick file edits — do them directly in the parent
  • Durable long-running work — use cron jobs or background terminals

Handle Interruptions Gracefully

Since delegate_task is synchronous, interrupting the parent cancels all active children. For critical work, consider saving intermediate results to the shared workspace so they can be resumed.

9. Conclusion

Hermes Agent's sub-agent delegation system is a powerful mechanism for scaling AI agent capabilities beyond the limits of a single context window. By spawning isolated child agents that work in parallel and return only their final summaries, the parent agent can orchestrate complex workflows without drowning in intermediate data.

The key principles to remember are:

  1. Context is king — always pass everything the sub-agent needs explicitly
  2. Isolation is the feature — fresh context means unbiased, focused work
  3. Parallelism is free — independent tasks should always run concurrently
  4. Keep it simple — don't delegate what you can do directly
  5. Use the right tool — sub-agents for task isolation, profiles for identity isolation

Whether you're running parallel research, orchestrating a multi-step content pipeline, or conducting a multi-agent debate on stock analysis, delegate_task gives you the primitives to build sophisticated agent workflows that stay clean, fast, and focused.
